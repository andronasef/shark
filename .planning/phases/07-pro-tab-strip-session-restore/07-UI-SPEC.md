# Phase 7 — UI Design Contract

> Visual and interaction contract for the Pro Tab Strip and Session Restore. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Platform: native macOS 14+ (Swift 6, SwiftUI with AppKit bridges). Units are **points (pt)**. Colours are NSColor / SwiftUI semantic names, never hex, so light/dark mode and Increase Contrast adapt automatically.
> Sources: 07-CONTEXT.md (locked decisions, cited as `[CTX]`), PRODUCT.md (`[PRODUCT]`), direction contract `.impeccable/surfaces/sources-shark-views-contentview-swift.md` (`[DIR]`), REQUIREMENTS.md TAB-01..07 (`[REQ]`). Calls made by this researcher, where upstream was silent or ambiguous, are tagged `[DECISION]` and justified.

## Native Building Blocks

These are the APIs the executor should use. The list is not exhaustive, and any SwiftUI or AppKit API is allowed. Nothing new gets added to `Package.swift`.

| Need | API | Notes |
|------|-----|-------|
| Strip overflow scrolling | `ScrollView(.horizontal, showsIndicators: false)` + `ScrollViewReader.scrollTo(activeTabID)` | Keeps the active tab visible on select, open or restore `[CTX]` |
| Tooltip | `.help(String)` | Content is defined in the Copywriting section |
| Context menu | `.contextMenu { }` with `Picker`/`Menu` for Colour | Native NSMenu rendering (13pt system menu font, which comes from the system and is not declared here) |
| Reorder | `.draggable(tab.id.uuidString)` + `.dropDestination(for: String.self)` (or `.onDrag`/`.onDrop`) | `[CTX]` |
| Middle-click | `NSViewRepresentable` overlay overriding `otherMouseUp(with:)` where `buttonNumber == 2` | `[DECISION]` An overlay is preferred over a global `NSEvent` monitor because it hit-tests per tab with no frame bookkeeping. It must pass every other event through (`hitTest` returns nil unless the current event is `.otherMouseDown`/`.otherMouseUp`). |
| Folder icon | `NSWorkspace.shared.icon(forFile: path)` sized 14×14 | Uses the active pane path `[CTX]` |
| Tab commands | `CommandMenu("Tab")` + `@FocusedValue` / app-level `WorkspaceState` | Real menu items. The hidden zero-opacity buttons for tab shortcuts are removed `[CTX]` |
| Copy Path | `NSPasteboard.general` `.string` | POSIX path of the active pane |
| Hot reload | `@ObserveInjection` + `.enableInjection()` on `TabStripView` and `TabItemView` | Existing pattern |

## Spacing Scale

Declared values (multiples of 4, in pt):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Gap between tint dot, folder icon, title and lock glyph; inset of the close button from the tab's leading edge |
| sm | 8pt | Horizontal padding inside a tab (leading and trailing); "+" button horizontal padding |
| md | 16pt | Close-button slot width (reserved on **both** sides so the title stays optically centred); hit area of the close and "+" buttons (16×16 hover circle) |
| lg | 24pt | Not used in this phase |
| xl | 28pt | Strip height `[CTX]`; "+" button width (28×28 hit area) |
| 2xl | 40pt | Pinned tab width `[CTX]` |
| 3xl | 120 / 260pt | Unpinned tab min / max width `[CTX]` |

Exceptions (sizes, not spacing):
- **0.5pt** hairlines: inter-tab separators, the strip's top and bottom edges, the active tab's side edges `[CTX]`
- **14pt** folder icon (14×14) `[CTX]`
- **8pt** tint dot diameter `[CTX]`
- **2pt** drag insertion indicator width
- **No corner radius** on tabs. Finder/Safari tabs are flush rectangles that meet at hairlines. `[DECISION]` This replaces the current 6pt rounded capsule.

### Strip layout (left to right)

```
| [pinned 40][pinned 40] | [tab][tab][tab] … (scrolls) | <empty strip area> | [+ 28] |
```

- **Pinned group:** fixed at the leading edge, outside the scroll view, so it never scrolls away. Each pinned tab is 40×28. `[CTX]` `[DECISION]` on the fixed placement.
- **Unpinned group:** each tab is `clamp((available − pinnedWidth − 28) / unpinnedCount, 120, 260)`. `[CTX]`
  - When the clamp hits 260, tabs are left-aligned and the leftover width is **empty strip area**, which is the target for double-click-to-open-a-new-tab `[DECISION]`. This keeps the locked 260pt max and gives that gesture a hit target.
  - When the clamp hits 120, the group scrolls horizontally with indicators hidden, and the active tab is scrolled into view (animated per Motion).
- **"+" button:** fixed at the trailing edge, outside the scroll view, 28×28 hit area, `plus` glyph.
- **Strip** is full width across the detail column, directly under the unified toolbar, 28pt tall, and visible even with one tab `[CTX]`. This replaces the current 22pt inset capsule and its outer padding (no padding around the strip).

### Unpinned tab internal layout

```
[8][close 16][4] ——— (dot 8)(4)(icon 14)(4) Title…(4)(lock) ——— [4][balance 16][8]
```

- The centred group is horizontally centred inside the tab, and the title truncates in the middle (`.truncationMode(.middle)`) `[CTX]`.
- The 16pt close slot sits on the leading edge `[CTX]`, with a mirrored 16pt empty "balance" slot on the trailing edge. Both are always reserved, so the title does not shift when the close button appears.
- The dot appears only when a colour is set, and the lock only when the tab is locked.

### Pinned tab internal layout

- The 14pt folder icon is centred in 40×28 `[CTX]`. There is no title and no close button `[CTX]`.
- A tint (if set) is an 8pt dot overlaid at the icon's bottom-trailing corner, offset (+4, +4), with a 1pt ring in the strip background colour. `[DECISION]` Icon-only tabs have no room for a leading dot.
- The lock state is not drawn on pinned tabs. It is announced in the tooltip and the accessibility value. `[DECISION]`

## Typography

Exactly 3 sizes and 2 weights are declared for this phase. Context menus and the Tab menu use the system NSMenu font, which is not overridden.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Tab title (active and inactive) | 11pt (`.system(size: 11)`) | Regular (400) | Single line, `lineLimit(1)`, vertically centred in 28pt (effective 1.0; no wrapping ever) |
| Close glyph `xmark` / lock glyph `lock.fill` | 9pt | Semibold (600) | n/a (glyph, centred in its 16pt slot) |
| "+" glyph `plus` | 12pt | Semibold (600) | n/a (glyph, centred in 28×28) |

- The active and inactive title weights are the **same** (Regular). In Finder the active tab is distinguished by its fill, not by weight. `[DECISION]` This replaces the current semibold-when-active styling.
- 11pt follows the direction contract's "SF Pro 13/11" pairing `[DIR]` and sits within the CONTEXT 11–12pt range `[CTX]`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Color(nsColor: .windowBackgroundColor)` | Active tab fill. It joins the unified toolbar visually, as Finder/Safari active tabs do. |
| Secondary (30%) | `windowBackgroundColor` + recess overlay `Color.black.opacity(0.06)` in light, `Color.black.opacity(0.20)` in dark | Strip background, inactive tabs, empty strip area, pinned tabs when inactive |
| Lines | `Color(nsColor: .separatorColor)` at 0.5pt | Inter-tab separators, strip top and bottom edges, active tab side edges |
| Text | `labelColor` for the active title; `secondaryLabelColor` for inactive titles, the close glyph, the lock glyph and the "+" glyph | |
| Hover | `Color.primary.opacity(0.05)` over an inactive tab; `Color.primary.opacity(0.10)` 16pt circle behind the close glyph and "+" on hover; `0.15` while pressed | |
| Accent (10%) | `Color.accentColor` (system accent, follows user setting) | Reserved list below only |
| Tint dots | `Color(nsColor: .systemRed / .systemOrange / .systemYellow / .systemGreen / .systemBlue / .systemPurple / .systemGray)` | The tab's 8pt tint dot and the swatches in the Colour submenu only. These are the Finder tag colours `[CTX]`. No other custom colour `[DIR]`. |
| Destructive | none | This phase has no destructive actions. Closing a tab is reversible via ⇧⌘T, so close affordances stay neutral (`secondaryLabelColor`, never red). |

`[DECISION]` on "Active tab uses the content background" `[CTX]`: this is read as the **window** background (`windowBackgroundColor`), not the file list's `controlBackgroundColor`. In real Finder and Safari, the active tab matches the toolbar/titlebar tone and inactive tabs are recessed darker. A white `controlBackgroundColor` tab in light mode would break the Finder look `[PRODUCT]`.

**Active tab edges:** a 0.5pt `separatorColor` hairline on the leading and trailing sides. There is **no** bottom hairline under the active tab, so it opens into the content. The strip's bottom hairline runs under inactive tabs only. Separators adjacent to the active tab are suppressed so its sides are not drawn twice.

**Accent reserved for (exhaustive):**
1. The 2pt drag-reorder insertion indicator, a vertical bar the full strip height in the drop gap.
2. The system keyboard focus ring, if a tab receives keyboard focus via Full Keyboard Access.

The accent is **not** used for the active tab, the active title, folder icons or the "+" button. This replaces the current `.accentColor` folder glyph on the active tab.

**Increase Contrast:** semantic colours adapt on their own. Additionally, when `colorSchemeContrast == .increased`, hover overlays double (0.05 → 0.10, 0.10 → 0.20) and the recess overlay goes to 0.10 light / 0.30 dark.

## Interaction Contract

### States per tab

| State | Visual |
|-------|--------|
| Active | Dominant fill, `labelColor` title, side hairlines, no bottom hairline |
| Inactive | Secondary (recessed) fill, `secondaryLabelColor` title, 0.5pt separators |
| Inactive + hover | + `primary 0.05` overlay; close glyph fades in (0.1s ease-out) |
| Active + hover | Close glyph fades in. The close glyph shows **only on hover**, for every tab including the active one `[CTX]` |
| Pinned | 40pt icon-only; no close glyph, ever `[CTX]` |
| Locked | `lock.fill` 9pt after the title `[CTX]`; tooltip appends "Locked" |
| Coloured | 8pt dot before the folder icon `[CTX]` |
| Being dragged | System drag preview of the tab; the source slot stays in place at 0.4 opacity until the drop |
| Drop target gap | 2pt accent insertion bar between tabs |

### Pointer gestures

| Gesture | Target | Result | Source |
|---------|--------|--------|--------|
| Click | Tab | Select tab | existing |
| Click | Close glyph | Close the tab (a locked tab closes too; see Lock) | `[CTX]` |
| Middle-click | Tab (pinned or not) | Close that tab without selecting it | `[CTX]` `[REQ TAB-02]` |
| Double-click | Empty strip area (right of the last tab, or anywhere in a one-tab strip outside the tab) | New tab at the active tab's active-pane path, inserted at the end, selected | `[CTX]` |
| Double-click | A tab | No action (it was selected on the first click) | `[DECISION]` Prevents accidental duplicates |
| Click | "+" | New tab at the active path, inserted after the current tab, selected | `[DECISION]` Matches Safari ⌘T placement |
| Drag | Tab | Reorder within its group. Pinned tabs drop only in the pinned group and unpinned only in the unpinned group. Drops across groups snap to the nearest valid gap. | `[CTX]` |
| Right-click / ⌃-click | Tab | Context menu (below) | `[CTX]` |
| Hover 0.5s+ | Tab | Tooltip (system `.help` delay) | `[CTX]` |
| ⌘-double-click / ⌘-Return | Folder in a pane | Open in a new **background** tab inserted after the current tab; the current tab stays selected | `[CTX]` `[REQ TAB-07]` |
| Middle-click | Folder in a pane, sidebar item, breadcrumb segment | Same as ⌘-double-click | `[CTX]` `[REQ TAB-07]` |
| ⌘-click | Sidebar item, breadcrumb segment | Same as ⌘-double-click | `[REQ TAB-07]` |

### Lock behaviour

- When a folder is activated (double-click or Return) in a locked tab, it opens in a new tab inserted directly after the locked tab, and that new tab is **selected** (foreground). The locked tab's path does not change. Back and Forward still work in the locked tab. `[CTX]` `[DECISION]` on foreground: the user asked to go there, unlike ⌘-open, which is explicitly background.
- `[DECISION]` A locked tab can still be closed explicitly (close glyph, ⌘W, middle-click, Close Tab), because ⇧⌘T makes closing reversible. **Bulk closes skip locked tabs:** Close Other Tabs and Close Tabs to the Right keep pinned **and** locked tabs (QTTabBar convention).

### Context menu (exact order and labels)

```
New Tab
Duplicate Tab
─────────────
Pin Tab            ↔ Unpin Tab
Lock Tab           ↔ Unlock Tab
Colour            ▸  None ✓ │ ─ │ ● Red │ ● Orange │ ● Yellow │ ● Green │ ● Blue │ ● Purple │ ● Grey
─────────────
Copy Path
─────────────
Close Tab
Close Other Tabs
Close Tabs to the Right
─────────────
Reopen Closed Tab
```

- The Colour submenu shows a checkmark on the current choice, and each item has an 8pt dot image in its colour.
- Duplicate Tab inserts a copy directly after the source and selects it. The copy carries over panes, split state, view settings, colour and pin state; it does **not** carry over Lock. `[DECISION]` A duplicate is usually made to wander away from the original.
- Disabled states: Close Other Tabs is disabled when no other closable tab exists. Close Tabs to the Right is disabled when no closable tab is to the right. Reopen Closed Tab is disabled when the history is empty. New Tab, Duplicate, Pin, Lock, Colour, Copy Path and Close Tab are always enabled.
- Pinning moves the tab to the end of the pinned group. Unpinning moves it to the start of the unpinned group. `[DECISION]` Safari behaviour.

### Keyboard and Tab menu

`CommandMenu("Tab")` is inserted after the View menu, with this exact order:

| Item | Shortcut | Notes |
|------|----------|-------|
| New Tab | ⌘T | At the active path, after the current tab |
| Close Tab | ⌘W | Closing the last tab leaves one tab at Home; the window stays open `[CTX]` |
| Reopen Closed Tab | ⇧⌘T | Restores at the original index when possible, otherwise the end; selected |
| Recently Closed ▸ | none | Up to 20 items, most recent first. Each item's title is the tab title, and choosing one reopens it. The submenu item is disabled when the history is empty. `[REQ TAB-03]` |
| ─ | | |
| Show Next Tab | ⌃Tab, also ⇧⌘] | Wraps around |
| Show Previous Tab | ⌃⇧Tab, also ⇧⌘[ | Wraps around |
| Select Tab 1…8 | ⌥⌘1 … ⌥⌘8 | No-op if that tab does not exist |
| Select Last Tab | ⌥⌘9 | `[CTX]` |
| ─ | | |
| Duplicate Tab | none | |
| Pin Tab / Unpin Tab | none | Label toggles |
| Lock Tab / Unlock Tab | none | Label toggles |
| Copy Path | none | Active pane path; ⇧⌥⌘C is left for Phase 8 Explorer ergonomics |

- A `Commands` menu item can carry only one key equivalent, so the secondary shortcuts (⇧⌘] and ⇧⌘[) are bound with an `NSEvent` local monitor or hidden `keyboardShortcut` buttons. The visible menu shows ⌃Tab / ⌃⇧Tab. `[DECISION]`
- ⌘1–4 stay Finder view modes and are unchanged `[CTX]`.
- Tab indices for ⌥⌘N count pinned tabs first, in visual order.

### Motion

- Tab insert, remove and reorder, and pin/unpin regrouping: `.spring(duration: 0.2, bounce: 0)` `[CTX]` (≤200ms).
- Close glyph and hover overlay: `.easeOut(duration: 0.1)`.
- Scroll-to-active on overflow: animated with the same spring.
- **Reduce Motion** (`accessibilityReduceMotion`): no movement. Insert and remove become a 0.15s opacity crossfade, and reorder and scroll-to-active jump with no animation `[PRODUCT]`.

## Session Restore (user-visible contract)

- On launch, the window shows the restored tabs, order, pinned group, locks, colours, active tab, split state, active pane and per-pane view mode, sort, hidden-file and icon-size settings **on its first frame**, with no flash of a default Home tab. `[REQ TAB-06]` `[DECISION]` The restore runs synchronously before the first `WindowGroup` body evaluates. It is a small JSON read, so it does not violate "never block the main thread" in spirit.
- After restore, the active tab is scrolled into view.
- Recently Closed (up to 20) is restored with the session, so ⇧⌘T works immediately after relaunch.
- There is no restore UI, prompt or "Restore previous session?" dialog. It always restores. A setting to disable this is deferred to Phase 10.
